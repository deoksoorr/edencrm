## 1. CRM 전체 개요와 메뉴 구조

EDEN CRM 은 **고객 유입 → 상담 → 견적 → 계약 → 공사(공정) → 정산 → 성과 분석**을 하나의 흐름으로 관리합니다.

```
고객 등록 → 영업 파이프라인(자동 단계) → 견적 → 계약 → 계약 '진행' 전환
   → 프로젝트 자동 생성 → 공정 보드 '대기중' → 공정 진행 → 준공검사 → (하자보수) → 전체완료
   → 프로젝트 완료 → 정산 완료
```

왼쪽 사이드 메뉴 구조(권한이 없는 메뉴는 보이지 않음):

| 구역 | 메뉴 | 하는 일 |
|---|---|---|
| — | **대시보드** | 역할별 홈 화면. 사장은 핵심 현황·출근 현황·최근 입금/출금·성과까지 한 화면 |
| **영업** | **고객 CRM** | 고객 등록·상세(활동/견적/계약/프로젝트 통합)·사업자등록증 관리 |
| | **영업 파이프라인** | 영업 기회를 7개 그룹 칸반으로 **조회**(단계는 자동 산정 — 6번 참조) |
| | **견적** | 견적 작성·버전 이력·인쇄, 기간 필터의 "기준 화면" |
| | **계약** | 계약·입금(분할 지급)·미수금·파기 관리 |
| **현장** | **프로젝트** | 공사 1건의 모든 것(개요/직원·일정/공정/지출/사진·문서/이력 6탭 — '지출' 탭은 R5 전 '원가' 탭의 새 이름) |
| | **공정 보드** | 대기중+19단계 칸반 — 모든 진행 공사의 현재 위치 |
| | **일정** | 월 캘린더 + 직원별 타임라인(오전/오후/야간 시간대) |
| | **작업일지** | 직원 작업 기록 — **시스템 설정의 '운영 기능' 토글이 켜져 있을 때만 메뉴가 보임**(기본 꺼짐) |
| **분석** | **직원 성과** | 직원별 확정 매출·순이익 기여·목표 달성률 |
| | **리포트** | 기간별 KPI·월별 추이·CSV + **직원 출근** 분석 탭 |
| **관리** | **직원 관리 / 목표 관리 / 시스템 설정 / 감사 로그** | 계정·권한, 월 목표, 운영 기능 토글, 변경 추적 |

역할 5종(사장/영업관리자/현장관리자/직원/회계)의 권한 매트릭스는 [USER_MANUAL — 테스트 계정과 역할별 권한](USER_MANUAL.md#테스트-계정과-역할별-권한) 참조.

## 2. 공통 기간 필터 사용법

**견적 · 계약 · 영업 파이프라인** 세 화면의 기간 필터는 같은 부품(공통 컴포넌트)을 쓰기 때문에
**같은 프리셋을 누르면 세 화면 모두 정확히 같은 날짜 범위**로 조회됩니다(자동 테스트로 고정 — QA 실측에서 세 화면의 날짜 경계가 문자 단위로 동일함을 확인).

화면 구성: `[기준 select(화면별)] [오늘] [이번 주] [이번 달] [지난달] [최근 3개월] [올해]  [시작일][종료일] [직접 지정]  [기간 초기화]`

| 프리셋 버튼 | 범위 규칙 |
|---|---|
| **오늘** | 오늘 하루 |
| **이번 주** | 이번 주 **월요일~일요일** (주 시작은 월요일) |
| **이번 달** / **지난달** | 해당 캘린더 월 1일~말일 |
| **최근 3개월** | **이번 달 포함 최근 3개 캘린더 월** (예: 7월에 누르면 5월 1일~7월 31일 — 오늘부터 90일 아님) |
| **올해** | 1월 1일~12월 31일 |
| **직접 지정** | 시작일·종료일 입력 후 [직접 지정] 클릭. 한쪽만 넣으면 그쪽만 제한(개구간). 시작>종료로 넣으면 자동으로 맞바꿈 |

사용 규칙:

- **기본값은 "전체"** — 아무 프리셋도 누르지 않으면 기간 제한 없이 전부 보입니다(세 화면 공통, 화면별 기본값 다르게 하지 않음).
- 프리셋을 누르면 날짜 입력 칸에 **계산된 실제 경계 날짜가 표시**됩니다 — 어떤 범위로 조회 중인지 화면에서 바로 확인할 수 있습니다.
- **[기간 초기화]** 링크는 기간만 지우고 검색어·상태 등 다른 필터는 유지합니다.
- 시작일과 종료일은 **양끝 포함**(폐구간)입니다.
- **기준 select**: 어떤 날짜 컬럼으로 자를지 고르는 select 1개가 화면별로 붙습니다(아래 3~5번). 필터를 적용하면 **목록 + 건수 + 합계 카드가 동시에** 그 기간 기준으로 바뀝니다.

## 3. 견적 탭 기간 조회

- 위치: **영업 > 견적** (`r=quotes.index`)
- 기준: **작성일** 고정(기준 select 없음 — 견적은 작성일 단일 기준).
- 필터 적용 시 상단 요약 「**조회 N건 · 총액(VAT 포함) ...원**」이 함께 갱신됩니다. 필터가 없으면 「전체 N건」.
- 목록 컬럼의 총액은 "공급가액 + 부가세 − 할인 · VAT 포함" 입니다(컬럼 도움말에 명시).

## 4. 계약 탭 기간 조회

- 위치: **영업 > 계약** (`r=contracts.index`)
- 기준 select 3종: **계약일**(기본) / **등록일** / **최근 입금일**
- 필터 적용 시 목록·건수와 함께 **합계 카드 3종(계약 총액 · 입금 총액 · 미수금)** 이 그 기간 기준으로 갱신되고, 라벨에 **「(필터 적용 합계)」** 가 붙습니다(마우스를 올리면 "아래 합계는 현재 검색·기간 필터가 적용된 계약 기준입니다").
- **'최근 입금일' 기준** 조회는 입금(paid) 기록이 있는 계약만 모집단이 됩니다 — 화면에도 안내가 표시됩니다: 「※ '최근 입금일' 기준 기간 조회는 입금(paid) 기록이 있는 계약만 포함합니다 — 입금 없는 계약은 목록·합계에서 제외됩니다.」
- 정렬 select 4종: 최근 입금순 / 오래된 입금순(입금 없는 계약은 항상 마지막) · 입금 없음 우선 / 입금 없음 후순위(등록순 유지, 입금 없음 그룹만 앞/뒤로).

## 5. 영업 파이프라인 기간 조회

- 위치: **영업 > 영업 파이프라인** (`r=pipeline.index`)
- 기준 select 2종: **등록일**(기본) / **최근 연락일** — 최근 연락일 기준은 연락 기록이 없는 리드가 제외됩니다.
- 필터 적용 시 7개 컬럼과 상단 요약 4종(진행 예상 금액 / 견적 진행 금액 / 계약 전환 / 보류·종료)이 함께 갱신됩니다.
- 과거에 쓰던 주소(북마크)의 옛 기간 값(`7d/30d/90d/month`)은 같은 범위의 새 필터로 **자동 변환**되므로 그대로 열어도 됩니다.

## 6. 영업 파이프라인이 조회 전용인 이유

R4 개편으로 파이프라인 보드에서는 **카드를 끌어서 단계를 바꾸는 기능, 카드에서 바로 고치는 기능이 제거**되었습니다
(화면에서 숨긴 것이 아니라 서버 기능 자체를 제거 — 주소로 직접 호출해도 동작하지 않음을 QA 가 확인).
화면 상단에도 명시되어 있습니다: 「단계는 원본 데이터(계약·견적·리드 단계) 기준 자동 산정 — 조회 전용」.

이유: 예전에는 보드의 단계와 실제 계약·견적 상태가 서로 어긋났습니다. 실데이터 점검에서
"계약이 진행 중인데 파이프라인은 아직 '견적발송'", "계약이 파기됐는데 파이프라인은 '계약대기'로 살아남아
예상 금액 3,300만 원을 부풀리는" 사례가 확인됐습니다. 사람이 카드를 옮기는 방식으로는 이 불일치를 막을 수 없어,
**보드의 단계는 원본 데이터에서 자동으로 계산해 보여주기만** 하도록 바꿨습니다.

그래서 상태 변경은 각 **원본 메뉴**에서 하면 보드에 자동 반영됩니다:

| 바꾸고 싶은 것 | 어디서 | 보드 반영 |
|---|---|---|
| 계약 체결·보류·파기 | **영업 > 계약** | 자동 (계약 그룹/종료 그룹으로 이동) |
| 견적 발송·수락 | **영업 > 견적** | 자동 (견적 진행 그룹) |
| 리드 자체 정보(담당·예상 금액·12단계 등) | 보드 카드 클릭 → 상세 페이지 → **[수정]** | 자동 재산정 |

카드를 클릭하면 상세 페이지로 이동하며, 상세·수정·삭제와 바로가기(견적/계약 등)는 그대로 사용할 수 있습니다.

## 7. 파이프라인 단계 자동 산정 기준

보드 컬럼은 7개 그룹입니다: **신규 문의 → 상담 중 → 현장 확인 → 견적 진행 → 계약 / 보류 / 종료**.
하나의 리드가 여러 신호에 해당하면 **우선순위: 종료 > 보류 > 계약 > 견적 진행 > 현장 확인 > 상담 중 > 신규 문의** 로 하나만 정합니다.

산정 신호(강한 것부터):

1. **연결 계약** — 리드에 연결된 계약이 파기/취소면 '종료', 진행/보류/완료면 '계약'
2. **유효 견적** — 리드에 연결된 견적(임시저장 제외)이 있으면 '견적 진행' 이상
3. **고객 단위 보조 신호(추정)** — 그 고객의 영업 기회가 1건뿐일 때만, 리드 등록 이후 성립한 계약을 근거로 '계약'/'종료' 추정. 카드에 **「계약 C번호·추정」** 처럼 추정임이 표기됨
4. **리드의 12단계 값(fallback)** — 위 근거가 없으면 기존 12단계를 7그룹으로 매핑(예: 견적작성·견적발송·협상중·계약대기 → 견적 진행)

카드의 단계 배지에 마우스를 올리면 **어떤 근거로 산정됐는지**가 표시됩니다("자동 산정: ...").
상담 중·현장 확인 그룹은 현재 데이터 구조상 12단계 값으로만 판정합니다. '장기미응답' 단계의 귀속(보류로 잠정 처리)은 **정책 미확정**입니다.
매핑표 전체·정합성 규칙·리드-계약 연결 후보 점검 절차는 **[SALES_PIPELINE_RULES.md](SALES_PIPELINE_RULES.md)** 참조.

## 8. 고객 CRM과 사업자등록증 관리

법인·개인사업자 고객의 사업자 정보를 고객 화면에서 함께 관리합니다.

- **등록**: 고객 등록/수정 화면(**영업 > 고객 CRM** → [신규 고객 등록] 또는 [수정])에서
  **「사업자 여부 (사업자등록증 보유 고객)」** 를 켜면 입력 칸이 나타납니다 —
  사업자등록번호 / 상호(법인명) / 대표자명 / 사업장 소재지 / 업태 / 종목 / **사업자등록증 파일 (PDF·JPG·JPEG·PNG, 최대 10MB)**.
- **번호 형식 검증**: 사업자등록번호는 숫자 10자리를 000-00-00000 로 저장하며, **국세청 검증번호(체크섬)까지 확인**합니다.
  틀린 번호는 저장이 거부됩니다 — "사업자등록번호가 올바르지 않습니다."
- **중복은 경고만**: 같은 번호의 고객이 이미 있으면 "동일 사업자등록번호 고객이 이미 있습니다: ..." 경고가 뜨지만 저장은 막지 않습니다(지점·사업부가 같은 번호를 쓰는 경우가 있어 차단하지 않음).
- **목록 배지**: 고객 목록의 사업자 고객 행에 **「등록증」/「등록증 없음」** 배지가 표시됩니다. 고객 상세에는 '사업자 정보' 카드와 '사업자등록증' 카드(미리보기/다운로드/교체/삭제)가 나옵니다.
- **보안**: 파일은 웹에서 직접 접근할 수 없는 보호 폴더에 난수 이름으로 저장되고, 확장자와 실제 파일 내용(MIME)을 **이중 검증**합니다 —
  위장 파일(.php, PHP 내용의 .png 등)은 전부 거부됨을 QA 가 실측했습니다("허용되지 않는 파일 형식" / "파일 내용이 확장자와 일치하지 않습니다").
  등록·교체·삭제는 고객 관리 권한(영업관리자·사장), 열람은 고객 열람 권한이 필요하고, 교체·삭제 내역은 감사 로그에 보존됩니다.

## 9. 계약 목록의 입금 수치 읽는 법

**영업 > 계약** 목록의 입금 관련 4개 컬럼(각 컬럼 머리글에 마우스를 올리면 같은 설명이 나옵니다):

| 컬럼 | 의미 | 주의 |
|---|---|---|
| **현재 입금 총액** | 순입금 = 정상 입금(입금완료) − 환불. VAT 포함 현금 기준 | 대기(pending)·취소된 입금은 불포함 |
| **마지막 입금일** | 정상 입금의 **입금일** 중 가장 최근 날짜 | **등록일·수정일이 아님**. 환불·대기 제외. 입금이 없으면 「입금 없음」 |
| **미수금** | max(0, 계약 총액(VAT 포함) − 순입금) | **작성중·파기/취소 계약은 「제외」** 로 표기(집계 모집단 아님) |
| **입금률** | 순입금 ÷ 계약 총액 × 100 | 총액 0원이면 '-' |

**파기/취소된 계약 행**은 다르게 읽어야 합니다: 순입금은 환불이 차감된 값 그대로 보여주되,
입금률은 **'-'** 로 표시됩니다 — 잔여 회차의 **청구가 중단**되어 분할 예정 금액과 입금 내역이 다를 수 있기 때문입니다(도움말: "파기/취소 계약 — 잔여 회차 청구 중단").

대시보드(사장)의 **「최근 입금」** 리스트는 입금 완료(paid) 건만 입금일 순으로 보여주고, 환불이 발생한 계약의 입금 행에는
**「환불 −금액」** 배지가 붙습니다. **「최근 출금(원가 지출)」** 리스트는 확정 원가의 지출일 순입니다 —
파기 환불은 원가가 아니므로 이 리스트에 나오지 않고 입금 리스트의 배지로 확인합니다(환불을 '출금'에 포함할지는 **정책 미확정**).

## 10. 계약 진행 처리와 프로젝트 자동 생성

계약 상태를 **'계약 진행'** 으로 바꾸는 순간 프로젝트가 자동 생성되고 공정 보드 '대기중' 칸에 올라갑니다.
프로젝트를 손으로 만들지 않는 것이 원칙이며(계약 1건 = 프로젝트 1건 강제), 계약 없는 예외 프로젝트는 사장만 사유 입력 후 생성할 수 있습니다.

**프로젝트 상세의 '지출' 표기(R5)**: 프로젝트 상세에서 비용을 관리하는 탭 이름이 '원가'에서 **'지출'** 로,
요약의 '원가 총액'이 **'지출 총액'** 으로 바뀌었습니다. **이름만 바뀐 것으로, 값·계산식·화면 주소는 그대로**입니다 —
상세의 '지출 총액'은 대시보드·리포트 회계 지표의 **'원가 총액'과 동일 값**이며(화면 도움말에도 병기),
회계 지표 쪽 표기('이번 달 원가 총액'·'원가 총액(확정 공사)' 등)는 유지됩니다. [ACCOUNTING_RULES.md](ACCOUNTING_RULES.md) 참조.

**프로젝트 상세 요약의 정보/금액 그룹 분리(R6)**: 프로젝트 상세 상단 '프로젝트 요약' 카드가 **두 그룹으로 나뉘었습니다** —
왼쪽 **정보 그룹**(고객 · 현장 주소 · 상태 · 현재 공정 · 담당 관리자 · 착공일 · 준공 예정일)과 오른쪽 **금액 그룹**(계약 총액(VAT 포함) · 확정 매출(공급가액) · 지출 총액 · 실제 순이익 — 우측 정렬).
데스크톱은 세로 구분선으로, 좁은 화면(≤720px)은 가로 구분선으로 두 그룹을 구분합니다. **금액 그룹은 재무 열람 권한(canFinance)이 있는 계정에만 표시**되며, 권한이 없으면 금액 블록 자체가 나오지 않습니다.
값·계산식은 이전과 동일하고 배치만 정리한 것입니다(적자는 붉은색, 지출 미입력은 '미입력'/순이익 '-').

절차·확인 방법·주의사항은 사용자 매뉴얼에 정리되어 있습니다:
**[6. 계약을 진행 상태로 변경](USER_MANUAL.md#6-계약을-진행-상태로-변경)** · **[7. 프로젝트 자동 생성 확인](USER_MANUAL.md#7-프로젝트-자동-생성-확인)**

## 11. 공정 보드 — 대기중 + 19단계

**현장 > 공정 보드**는 R4 에서 **'대기중(0) + 19단계'** 구조가 되었습니다(보드 컬럼 총 20개).
19번째 단계 **전체완료**가 신설되어, 준공검사·하자보수 뒤의 "이 공사는 공정상 완전히 끝났다"를 명확히 표시합니다.

| 그룹(보드 묶음) | 단계 |
|---|---|
| **대기중** | 대기중(착공 전 대기 — 새 계약이 자동 배치되는 곳) |
| **착공 준비** | 현장실측 · 도면작성 · 자재발주 · 착공준비 |
| **시공** | 양생/보양 · 고압세척 · 바탕처리(면처리) · 크랙보수🔒 · 퍼티/퍼팅 · 방수처리🔒 · 프라이머 · 1차도장 · 2차도장 · 3차도장(마감)🔒 · 건조양생 |
| **마무리** | 현장정리 · 준공검사🔒 |
| **하자보수** | 하자보수🔒 |
| **종결** | **전체완료🔒 (R4 신설, 19번째)** |

- 🔒 = 확인 필요 공정. 상단 탭은 **전체 / 대기중 / 착공 준비 / 시공 / 마무리·하자** 5개이며, '마무리·하자' 탭에 마무리·하자보수·종결 그룹이 함께 나옵니다.
- 보드에는 **진행 예정·진행 중·일시 중단·하자보수** 상태의 프로젝트만 표시됩니다. 완료·정산·취소·파기된 프로젝트는 보드에서 빠지므로(데이터 보존),
  전체완료에 도달한 완료 공사는 **프로젝트 상세**에서 확인합니다("전체완료 · 진행률 100%").
- 진행률은 단계 위치 기준 자동 계산이며 전체완료 = 100% 입니다.
- 카드 이동은 드래그 또는 프로젝트 상세 '공정' 탭의 '공정 변경' 폼 — 절차는 [USER_MANUAL 9번](USER_MANUAL.md#9-대기중다음-공정-이동) 참조.

## 12. 하자보수와 전체완료

권장 흐름은 **준공검사 → (하자 발견 시) 하자보수 → 전체완료** 이고, 하자가 없으면 준공검사에서 전체완료로 직행합니다
(준공검사·하자보수에서 전체완료로 이동할 때는 '공정 건너뜀' 확인 창이 뜨지 않음 — 권장 직행 흐름).

- **하자보수 건 관리**: 프로젝트 상세 > 공정 탭의 **'하자보수'** 카드에서 건별 등록·수정·삭제 — 내용/요청일/요청 접수자/처리 담당/처리 예정일/사진/메모/상태(접수→처리 중→완료).
  화면 설명 그대로: "미완료 하자가 있으면 '전체완료' 이동 시 경고됩니다".
- **전체완료 전환 게이트(경고 — 차단 아님)**: 전체완료로 옮길 때 서버가 5가지를 점검합니다 —
  ① 미완료 하자 ② 미수금 ③ 확정 원가 0건 ④ 준공일(실제 준공일) 미입력 ⑤ 최종 사진 없음.
  미충족 항목이 있으면 경고 목록이 뜨고, **예외 진행 사유를 입력해야만** 이동합니다(사유 없이 진행하면 "예외 진행 사유를 입력하세요" 오류).
  사유는 공정 이력에 `예외 완료: <사유> [미충족: …]` 형식으로 기록되어 나중에 추적할 수 있습니다. 모든 항목 충족 시에는 경고 없이 바로 이동합니다.
- **전체완료에서 하자보수로 되돌리지 않습니다.** 종결 후 하자가 재발하면 하자보수 건을 추가 등록해 건 단위로 관리합니다.
- 상세 규칙(게이트 기준값·권한·이력)은 **[PROCESS_FLOW.md](PROCESS_FLOW.md)** 참조.

## 13. 프로젝트 상세에서 일정 등록

프로젝트 상세 > **'직원·일정' 탭**에서 캘린더로 이동하지 않고 바로 일정을 등록·수정할 수 있습니다(R4 신설).

- **[+ 일정 등록]** 버튼 → 탭 안에 폼이 열림: 제목 · 참여 직원(복수) · 날짜 · **시간대(오전/오후/야간 버튼, 복수 선택)** · 유형 · 메모.
  프로젝트 연결은 자동입니다(현재 보고 있는 프로젝트에 연결).
- 시작·종료 시각은 따로 입력하지 않습니다 — 선택한 시간대 기준으로 자동 산출되어 참고 표시됩니다(오전 09~12 · 오후 13~18 · 야간 18~22).
- **충돌 경고**: 같은 직원이 같은 날짜·시간대에 이미 일정이 있으면 폼 아래에
  「**일정 충돌 경고** — 같은 날짜·시간대에 이미 잡힌 일정이 있습니다.」와 대상 목록이 표시되고,
  **[경고 무시하고 저장]** 을 눌러야만 겹쳐서 저장됩니다(차단이 아니라 승인식 — 캘린더와 동일한 규칙).
- 일정 관리 권한(현장관리자·사장)이 없으면 폼·수정/삭제 버튼이 나오지 않고 목록만 보이며, 열람 범위 제한이 있는 계정은 "내가 참여한 일정만 표시"로 안내됩니다.
- 반복 일정은 지원하지 않습니다(**정책 미확정** — 반복 주기·종료 조건 정책 확정 후 별도 설계).

## 14. 전체 캘린더와의 연동

프로젝트 상세의 일정 목록과 **현장 > 일정** 캘린더는 **같은 데이터**입니다(화면에도 "캘린더(일정 관리)와 동일 데이터"로 명시).
별도 복사본이 없으므로 **양방향 반영이 자동**입니다:

- 프로젝트 상세에서 등록한 일정 → 캘린더 월 화면·직원별 타임라인에 즉시 표시 (QA 실측 확인)
- 캘린더에서 드래그로 날짜를 옮긴 일정 → 프로젝트 상세 목록에 바뀐 날짜·시간대로 즉시 반영 (QA 실측 확인)

행의 삭제는 캘린더의 삭제와 동일하게 동작합니다(삭제 이력은 감사 로그 보존).

## 15. 직원 출근 분석 (R6 최종 구조)

출근 데이터의 원천은 직원 **작업 기록(work_logs)** 이며, 근태 화면은 작업일지 메뉴 토글과 **무관하게**
별도 토글 '근태 표시'(**관리 > 시스템 설정 > 운영 기능**, 기본 켜짐)로 노출됩니다(작업일지 메뉴는 기존대로 기본 꺼짐).

**R6 에서 근태 구조가 바뀌었습니다** — 상세 규칙은 **[근태 관리 규칙 — ATTENDANCE_RULES.md](ATTENDANCE_RULES.md)** 를 보세요. 요약:

- **휴가는 전면 비노출**되었습니다(기존 데이터는 DB 에 보존, 화면·통계·CSV·그래프 어디에도 표시하지 않음). 일정 유형에서 '휴가' 옵션이 사라졌고, 캘린더·대시보드·분석에서 휴가 항목 자체가 제거됐습니다.
- **지각·조퇴 자동 판정이 폐지**되고, **지각·무단결근을 관리자가 직접 등록**하는 구조로 바뀌었습니다(분석 '직원 출근' 탭의 관리자용 월간 캘린더).
- 이제 **통계는 3종만** 사용합니다: **출근 일수 · 지각 횟수 · 무단결근 횟수**(조퇴·휴가·미출근·출근율 지표 제거).

두 화면의 역할이 다릅니다:

| | **대시보드 요약** (사장 대시보드 '이번 달 출근 현황') | **분석 탭** (분석 > 리포트 > **직원 출근**) |
|---|---|---|
| 용도 | 이번 달을 한눈에 | 월·직원 단위 상세 분석 + **관리자 마킹** |
| 내용 | 직원별 **이름 · 출근 N일 · 지각/무단결근 뱃지**(값이 있을 때만) · '출근 분석 보기 →' 링크 | 연/월/직원/부서/재직 필터 · KPI(출근 총/평균/최다/최소·전월 증감 + 지각·무단결근 합계) · 직원×일자 그리드(●=출근 · **지**=지각(주황) · **결**=무단결근(적색)) · 직원별 출근 일수 비교(막대) · 월별 출근 추이(최근 6개월) · 상세 표(출근 일수/지각(회)/무단결근(회)/전월 출근/증감) · **CSV 다운로드** · (권한자) **관리자 마킹 캘린더** |

집계 기준(두 화면 동일 계산식 — `AttendanceService` 단일 출처, 화면에도 명시):

| 통계 | 산식 | 주의 |
|---|---|---|
| **출근 일수** | 작업 기록의 **고유 날짜 수** − **무단결근으로 등록된 날 제외** | 같은 날 여러 현장 기록해도 1일. 지각으로 등록된 날은 출근 일수에 **포함** |
| **지각 횟수** | 해당 월 **지각** 마크 수(관리자 등록) | 지각한 날도 출근 일수에는 그대로 포함 |
| **무단결근 횟수** | 해당 월 **무단결근** 마크 수(관리자 등록) | 무단결근 날은 출근 일수에서 제외 |

- **영업일(근무 예정) 수는 통계가 아니라 캘린더·막대 차트 축 참고용**으로만 씁니다(출근율 지표는 폐지 — 분모 왜곡 방지).
- 지각·무단결근은 **관리자가 등록한 것만** 집계합니다(자동 추정 없음). 등록 방법·중복 방지·해제·감사 기록은 [ATTENDANCE_RULES.md](ATTENDANCE_RULES.md) 참조.
- 사무·영업직처럼 작업 기록을 쓰지 않는 직원은 출근 0으로 나옵니다 — 집계 대상 범위는 **정책 미확정**이므로 수치를 근태 평가에 그대로 쓰지 마세요.
- **기준 근무시간 설정(`attendance_work_start`/`attendance_work_end`)은 자동 지각·조퇴 판정 폐지와 함께 설정 화면에서 숨겨졌습니다**(행 데이터는 보존 — 부록 참조).

## 16. 회계 수치 기준

화면의 모든 돈 수치는 **두 축**으로 나뉩니다. 요약만 적으면:

- **손익 축(공급가액, VAT 제외)** — 확정 매출·순이익·성과. 공사가 **완료(준공)** 된 프로젝트만, **준공일이 속한 달**에 인식.
- **현금 축(VAT 포함)** — 입금 총액·미수금·입금률. **입금일 기준**, 환불 차감.
- 원가는 **'확정' 상태만** 합산하며, "이번 달 원가 총액"(지출 발생일 기준)과 "원가 총액(확정 공사)"(준공월 귀속)은 **기준이 다른 별개의 정상 수치**입니다.

모든 카드에 기준이 함께 적혀 있고 마우스를 올리면 산출 기준 도움말이 나옵니다.
산식 전체·분할 지급·파기/환불 처리·알려진 트레이드오프는 **[ACCOUNTING_RULES.md](ACCOUNTING_RULES.md)** 를 보세요.
"확정 매출과 입금 총액이 왜 다른가"는 [USER_MANUAL 23번](USER_MANUAL.md#23-매출원가순이익-확인)에 예시와 함께 있습니다.

R4 QA 가 실측으로 확인한 대표 메시지와 조치입니다(메시지 문구는 실제 화면 그대로).
기존 공통 오류 13종은 [USER_MANUAL 24번](USER_MANUAL.md#24-자주-발생하는-오류와-해결)에 있습니다.

| 화면 메시지(실제 문구) | 언제 나오나 | 조치 |
|---|---|---|
| "사업자등록번호가 올바르지 않습니다." | 번호가 10자리가 아니거나 국세청 검증번호가 틀릴 때 | 사업자등록증 원본의 번호를 다시 확인해 입력(000-00-00000). 저장은 되지 않으며 기존 값은 유지됨 |
| "허용되지 않는 파일 형식" | 사업자등록증에 PDF·JPG·JPEG·PNG 외 파일을 올릴 때 | 허용 형식으로 변환해 다시 업로드 |
| "파일 내용이 확장자와 일치하지 않습니다." | 확장자만 바꾼 위장 파일을 올릴 때 | 원본 프로그램에서 올바른 형식으로 다시 저장해 업로드 |
| "동일 사업자등록번호 고객이 이미 있습니다: ..." | 같은 번호의 고객이 이미 등록돼 있을 때 | 경고일 뿐 저장은 됩니다 — 같은 고객을 두 번 만든 게 아닌지 기존 고객 상세를 먼저 확인 |
| 전체완료 이동 시 "전체완료 조건 미충족 항목: …" 경고 목록(예: "미완료 하자 1건" / "미수금 26,223,575원" / "준공일(실제 준공일) 미입력" / "최종 사진 없음") | 게이트 5항목 중 미충족이 있을 때 | 가능하면 원인을 먼저 해소(하자 완료 처리·잔금 수금·원가 입력·준공일 입력·사진 업로드). 불가피하면 예외 진행 사유를 입력하고 진행 — 사유는 공정 이력에 남음 |

| "일정 충돌 경고 — 같은 날짜·시간대에 이미 잡힌 일정이 있습니다." | 같은 직원 일정이 겹칠 때(프로젝트 상세 인라인 등록 포함) | 실수라면 날짜·시간대·인원 조정. 의도한 중복이면 [경고 무시하고 저장] |
| "비활성화된 기능" 안내 | 꺼져 있는 운영 기능(작업일지 등)의 화면에 접근할 때 | 사장이 **관리 > 시스템 설정 > 운영 기능**에서 해당 토글을 켜면 복원(권한 오류 아님) |

## 18. 관리자 점검 체크리스트

**매일 (대시보드 5분)**
- [ ] 핵심 현황 4카드 — 이번 달 확정 매출 / 입금 총액 / 원가 총액 / 실제 순이익에 이상 변동이 없는지
- [ ] **최근 입금** — 어제 입금이 다 올라왔는지, 「환불 −」 배지가 새로 생기지 않았는지
- [ ] **최근 출금(원가 지출)** — 모르는 지출이 없는지, 증빙 여부
- [ ] 직원 업무 현황 — 오늘 일정·직원 미배정 경고 칩
- [ ] 알림(종 아이콘) — 미수금·일정 관련 알림 처리

**매주 (10분)**
- [ ] **공정 보드** — 지연 프로젝트·검수 대기 카드 확인, '대기중'에 오래 머문 공사 착공 계획 점검
- [ ] **영업 파이프라인** — '다음 일정' 지난 카드(빨간 표시)·체류일(D+) 긴 카드 후속 지시
- [ ] (설정을 켠 경우) 대시보드 **영업·계약 현황 주의 칩** — '계약 대기 · 현재'/'계약 대기 지연(7일+)'/'연락 예정일 경과'/'3일+ 미접촉 고객' 확인. R5 부터 **기본 숨김**이며 켜는 방법은 [부록 설정 표](#부록--시스템-설정-키) 참조
- [ ] **계약 목록**(정렬: 입금 없음 우선) — 입금이 하나도 없는 진행 계약 확인, 미수금 상위 계약 독촉 지시
- [ ] 하자보수 카드 — 미완료 하자 건의 처리 예정일 초과 여부

**매월 (월초 30분)**
- [ ] **분석 > 리포트** — 지난달 확정 매출(공급가액)·확정 순이익·목표 달성률 확인(준공월 기준)
- [ ] 완료 처리 전 지출(원가) 입력 마감 — 지출 '미입력'·미확정(임시 저장/확인 대기) 상태로 완료된 공사가 없는지([USER_MANUAL 16번](USER_MANUAL.md#16-지출-총액-확인))
- [ ] **분석 > 리포트 > 직원 출근** — 지난달 출근율·전월 증감, 필요 시 CSV 보관
- [ ] **관리 > 목표 관리** — 이번 달 직원별 목표 입력(미입력 시 성과 화면에 '목표 미설정')
- [ ] **관리 > 감사 로그** — 입금 취소·계약 파기·파일 삭제 등 민감 행동 스팟 확인
- [ ] 계약 목록 합계 카드(지난달, 기준: 계약일)와 리포트 수치 대사 — 어긋나면 [QA_REPORT.md](QA_REPORT.md) 재검 방법 수행
