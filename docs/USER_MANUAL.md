# EDEN CRM 사용자 매뉴얼 (관리자용)

도장회사 업무 시스템 EDEN CRM 을 처음 쓰는 사장님·직원을 위한 안내서입니다.
고객 등록부터 계약, 공사(공정), 정산, 성과 확인까지 **실제 화면의 메뉴명·버튼명 그대로** 설명합니다.

- 접속: 브라우저에서 시스템 주소로 접속 → 로그인 화면에서 아이디·비밀번호 입력
- 화면 구조: 왼쪽 **사이드 메뉴**(대시보드 / 영업 / 현장 / 분석 / 관리) + 오른쪽 상단 **알림 종 모양 아이콘**·**내 계정**(비밀번호 변경 / 로그아웃)
- 이 문서에서 "화면 주소"는 `index.php?r=...` 뒤에 붙는 값입니다. (예: `r=contracts.index`)

## 테스트 계정과 역할별 권한

로컬 개발용 시드 기준 테스트 계정입니다. **비밀번호는 모두 `password123!`** 이며, 운영 배포 전 반드시 변경하세요.

| 아이디 | 이름 | 역할(화면 표기) | 주 용도 |
|---|---|---|---|
| `admin` | 김대표 | 슈퍼관리자(사장) | 모든 기능 |
| `leesh` | 이상훈 | 영업관리자 | 고객·영업·견적·계약 |
| `chays` | 차윤석 | 현장관리자 | 배정·공정·일정·원가 |
| `maeng` | 맹기현 | 직원 | 배정된 프로젝트 열람·작업일지 |
| `chaws` | 차우석 | 직원 | 배정된 프로젝트 열람·작업일지 |

> 회계(accountant) 역할도 시스템에 존재하지만 기본 시드에는 계정이 없습니다. 필요 시 **관리 > 직원 관리**에서 생성하세요.

("이 페이지 또는 기능에 접근할 권한이 없습니다.").

## 핵심 업무 흐름 한눈에 보기

```
고객 등록 → 영업 기회(파이프라인) → 견적 → 계약 등록 → 계약 '진행' 전환
   → 프로젝트 자동 생성 → 공정 보드 '대기중' → 공정 진행(착공준비→시공→마무리)
   → 검수(준공검사) → 완료 → 정산 완료
```

```mermaid
flowchart LR
  A[고객 등록] --> B[영업 기회]
  B --> C[견적]
  C --> D[계약 등록]
  D --> E["계약 '진행' 전환"]
  E --> F[프로젝트 자동 생성]
  F --> G["공정 보드 '대기중'"]
  G --> H[공정 진행<br>착공준비 → 시공]
  H --> I[검수<br>준공검사]
  I --> J[완료]
  J --> K[정산 완료]
```

핵심 규칙 두 가지만 기억하세요.

1. **프로젝트는 손으로 만들지 않습니다.** 계약을 '계약 진행' 상태로 바꾸면 프로젝트가 자동으로 생기고, 공정 보드의 '대기중' 칸에 올라갑니다. (계약 없는 예외 프로젝트는 사장만 생성 가능)
2. **돈 수치는 두 가지 기준이 있습니다.** 손익(매출·순이익)은 **공급가액(VAT 제외)**, 통장 돈(입금·미수금)은 **계약 총액(VAT 포함)** 기준입니다. 화면의 모든 금액 카드에 어느 기준인지 적혀 있습니다. (자세한 설명은 [23번](#23-매출원가순이익-확인))

## 업무별 사용법

### 1. 고객 등록

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | 사이드 메뉴 **영업 > 고객 CRM** → 오른쪽 위 **[신규 고객 등록]** 버튼 (화면 주소 `r=customers.form`) |
| **사용 목적** | 문의가 들어온 고객(개인/법인)의 연락처·현장·관심 공사를 기록해 이후 영업·견적·계약의 출발점으로 삼습니다. |
| **등록 순서** | ① 구분(개인/법인) 선택 — 법인이면 업체명·담당자 칸이 추가로 나타남 ② 고객명 입력 ③ 연락처·이메일 입력(입력 칸을 벗어나면 중복 고객 자동 확인) ④ 주소·현장주소 ⑤ 유입경로·관심공사·예상규모·예상예산(원)·상담희망일 ⑥ 담당영업 선택 ⑦ 상태(활성/비활성/블랙리스트)·다음연락예정일·태그·내부메모 ⑧ **개인정보 수집·이용에 동의합니다** 체크 ⑨ **[저장]** |
| **필수 입력값** | 구분, 고객명, 개인정보 동의 체크 |
| **저장 후 확인 위치** | **영업 > 고객 CRM** 목록에 새 행이 보이고, 고객명을 누르면 고객 상세(활동 이력·견적·계약·프로젝트 통합 화면)로 이동합니다. |
| **수정 방법** | 고객 상세 → **[수정]** → '고객 정보 수정' 화면에서 변경 후 **[저장]** |
| **취소·파기 방법** | 거래 중지는 상태를 '비활성' 또는 '블랙리스트'로 변경(기록 보존, 권장). 완전 삭제는 삭제 권한이 있는 사장만 가능합니다. |
| **주의사항** | 연락처·이메일이 기존 고객과 겹치면 노란 경고 상자에 "중복 의심 고객: ..."이 표시됩니다 — 같은 고객을 두 번 만들지 말고 기존 고객 상세를 사용하세요. 고객 등록·수정은 영업관리자·사장만 가능합니다. |

### 2. 영업 기회 등록

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | **영업 > 영업 파이프라인** → 오른쪽 위 **[+ 신규 영업기회]** 버튼 (화면 주소 `r=pipeline.index`) |
| **사용 목적** | "이 고객과 이 공사 건이 지금 어느 단계까지 왔는가"를 칸반 보드로 관리합니다. 단계는 12개: 신규문의 → 상담예약 → 현장실측 → 견적작성 → 견적발송 → 협상중 → 계약대기 → **계약완료**(수주) / 보류 · 장기미응답 · **실주** · **취소** |
| **등록 순서** | ① [+ 신규 영업기회] 클릭(팝업) ② 고객 선택 ③ 단계·담당영업 선택 ④ 공사종류·현장주소 입력 ⑤ 예상계약금액·예상원가·성공확률(%) ⑥ 다음연락예정일·태그·메모 ⑦ **[저장]** |
| **필수 입력값** | 고객 |
| **저장 후 확인 위치** | 파이프라인 보드의 해당 단계 칸에 카드가 나타납니다. 상단 그룹 탭(전체/신규·상담/현장·견적/계약/보류·종료)과 검색·담당영업·공사종류·기간 필터로 찾을 수 있습니다. |
| **수정 방법** | 카드를 클릭 → 오른쪽 상세 패널에서 단계 변경·담당 영업·다음 연락일 바꾸고 **[변경 저장]**. 전체 항목 수정은 **[상세 수정]**. 단계만 옮길 때는 카드를 **마우스로 끌어서(드래그)** 다른 단계 칸에 놓으면 됩니다. |
| **취소·파기 방법** | 진행이 끝난 건은 카드를 '실주' 또는 '취소' 단계로 이동(기록 보존, 권장). 잘못 만든 카드는 상세 패널의 **[삭제]**. |
| **주의사항** | '계약완료' 단계 카드에는 **[계약 등록]** 바로가기가 생깁니다. 예상 금액은 공급가액 기준으로 대시보드의 '예상 매출(가중·공급가액)'에 성공확률을 곱해 반영됩니다. 등록·이동은 영업관리자·사장만 가능합니다. |

### 3. 견적 등록

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | **영업 > 견적** → **[+ 견적 등록]** 버튼 (화면 주소 `r=quotes.form`) |
| **사용 목적** | 공사 항목별 금액을 계산해 고객에게 제시할 견적서를 만들고, 수정할 때마다 버전 이력을 남깁니다. |
| **등록 순서** | ① 고객 선택 ② (선택) 연결 영업기회(리드) 선택 ③ 유효기간·상태(임시저장/발송됨/수락됨/거절됨/만료됨) ④ 특이사항 ⑤ '견적 항목'에서 **[+ 행 추가]** 로 항목 입력 — 항목명 / 면적(㎡) / 수량 / 단가 / 재료비 / 인건비 / 장비비 / 외주비 / 기타비용 (금액 자동 계산) ⑥ 필요 시 할인 금액 입력 ⑦ 버전 메모(수정 사유) ⑧ **[저장]** |
| **필수 입력값** | 고객, 견적 항목 1행 이상 |
| **저장 후 확인 위치** | 견적 관리 목록과 견적 상세. 하단 합계에 **공급가액(VAT 제외) / 부가세 / 총액(VAT 포함)** 이 자동 계산되어 표시됩니다. 견적 상세의 인쇄 화면으로 고객 제출용 출력이 가능합니다. |
| **수정 방법** | 견적 상세 → **[수정]** → 저장하면 **새 버전**으로 이력이 쌓입니다(이전 버전 보존). |
| **취소·파기 방법** | 상태를 '거절됨' 또는 '만료됨'으로 변경(권장). 삭제는 견적 관리 권한자(영업관리자·사장)만 가능합니다. |
| **주의사항** | 부가세는 **할인 전 공급가액** 기준으로 계산되고 할인은 총액에서 차감됩니다(화면 도움말에도 명시). 계약으로 전환된 뒤 견적을 수정해도 **계약에 저장된 '원본 견적액'은 변하지 않습니다.** |

### 4. 견적에서 계약 생성

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | **영업 > 계약** → **[+ 계약 등록]** (화면 주소 `r=contracts.form`). 또는 견적 상세의 **[계약으로 전환]** 버튼으로 바로 진입. |
| **사용 목적** | 수락된 견적을 골라 계약서를 만들면 고객·공사 정보·금액이 자동으로 채워져 다시 입력할 필요가 없습니다. |
| **등록 순서** | ① 계약 등록 화면 맨 위 '연결 견적' 카드에서 견적번호·고객명으로 검색 ② **연결 견적 선택** ③ 다음 값이 자동 입력됨 — 고객 / 공사명 / 현장 주소 / 공사 유형 / 계약 총액(VAT 포함) / 공급가액·부가세 / 특약사항 / 메모 / 담당 영업 ④ 필요한 값 수정(자동 입력 값은 기본값일 뿐 수정 가능) ⑤ 계약 총액을 견적과 다르게 바꾸면 '할인·증액 사유' 칸이 나타남 — 사유 입력 ⑥ 계약일·착공예정일·준공예정일·하자보증기간·계약서 파일(선택) ⑦ 대금 지급 계획 입력([5번](#5-계약금중도금잔금-비율-설정)) ⑧ **[저장]** |
| **필수 입력값** | 고객, 계약 총액(VAT 포함) |
| **저장 후 확인 위치** | 계약 상세의 **'견적 전환 정보 (원본 견적 불변)'** 카드 — 원본 견적액(버전 표기), 할인/증액 금액, 최종 계약액, 전환 일시·처리자. 계약 상세 상단에는 원본견적 번호 링크가 표시됩니다. |
| **수정 방법** | 계약 상세 → **[수정]**. 연결 견적을 바꾸거나 금액을 조정할 수 있습니다. |
| **취소·파기 방법** | [19번 계약 취소·파기](#19-계약-취소파기) 참고. |
| **주의사항** | 이미 다른 계약에 연결된 견적은 목록에 "— 다른 계약에 연결됨"으로 표시되고 선택할 수 없습니다. 견적을 불러와도 **원본 견적은 절대 변경되지 않습니다.** 견적 없이 직접 등록('견적 없이 직접 등록' 선택)도 가능합니다. |

### 5. 계약금·중도금·잔금 비율 설정

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | 계약 등록/수정 화면 하단 **'대금 지급 계획 — 계약금·중도금·잔금'** 카드 |
| **사용 목적** | 계약 총액을 계약금/중도금/잔금으로 나눠 입금 일정을 만들고, 저장하면 입금 예정 내역이 자동으로 생성·동기화됩니다. |
| **등록 순서** | ① 계약금 비율(%) 입력 ② 중도금 비율(%) 입력 ③ 잔금 비율(%) 입력 — **세 비율의 합이 정확히 100** 이어야 함 ④ 각 칸 아래에 "계약금 20% → 6,600,000원"처럼 계산 금액이 실시간 표시됨 ⑤ 유형별 예정일 입력(해당 유형의 입금 내역이 아직 없을 때만) ⑥ **[저장]** |
| **필수 입력값** | 세 비율(합계 100%). 계약금·중도금 **금액을 직접 입력**하면 비율이 자동으로 다시 계산됩니다. |
| **저장 후 확인 위치** | 계약 상세의 '계약금/중도금/잔금' 행(금액과 % 함께 표기)과 **'입금 관리'** 표 — 유형별 대기(pending) 예정 행이 자동 생성됩니다. |
| **수정 방법** | 계약 수정 화면에서 비율 또는 금액을 바꾸고 저장 — **대기(pending) 예정 행만** 새 금액으로 동기화되고, 입금완료·환불 내역은 절대 변경되지 않습니다. |
| **취소·파기 방법** | 별도 취소 개념 없음 — 비율을 다시 조정해 저장하면 됩니다. 입금 내역 자체의 취소는 계약 상세 '입금 관리'의 [취소] 버튼(기록 보존형). |
| **주의사항** | 계산 기준은 **계약 총액(VAT 포함)** 입니다. 금액 = 총액 × 비율 반올림이며, 반올림에서 생기는 끝자리 차이는 **잔금이 흡수**합니다(그래서 잔금 금액 칸은 자동 계산·수정 불가). 합계가 100%가 아니면 "분할 비율 합계가 100%가 되어야 합니다. (현재 110%)" 같은 메시지와 함께 **저장이 차단**됩니다. |

### 6. 계약을 진행 상태로 변경

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | 계약 상세(`r=contracts.show`) → **[수정]** → '상태'를 **계약 진행** 으로 변경 → **[저장]**. 또는 계약 상세 상단의 **[프로젝트로 전환]** 버튼(확인 창에서 [전환]). |
| **사용 목적** | 계약이 실제로 체결되어 공사를 시작한다는 표시입니다. 이 순간 프로젝트가 자동 생성됩니다. |
| **등록 순서** | ① 계약 상세 → [수정] ② 상태: 작성중 → **계약 진행** ③ [저장] ④ 초록색 알림 "계약이 저장되었습니다. 프로젝트가 자동 생성되었습니다."와 함께 **'프로젝트 보기 →'** 링크 표시 |
| **필수 입력값** | 상태 변경만 하면 됩니다(계약 총액은 이미 필수 입력됨). |
| **저장 후 확인 위치** | 계약 상세 상단에 **[프로젝트 보기 (P번호)]** 버튼이 생깁니다. 미수금 집계에도 이때부터 포함됩니다(작성중 계약은 '제외(작성중)'으로 표기). |
| **수정 방법** | 상태는 언제든 수정 화면에서 변경 가능: 작성중 / 계약 진행 / 계약 보류 / 계약 완료 / 계약 취소 / 계약 파기 |
| **취소·파기 방법** | [19번](#19-계약-취소파기) 참고. |
| **주의사항** | 진행 → 보류 → 진행처럼 여러 번 오가도 프로젝트는 **1건만 유지**됩니다(중복 생성 안 됨). 이미 프로젝트가 있으면 "계약이 저장되었습니다. 연결된 프로젝트가 이미 존재합니다." 알림과 함께 기존 프로젝트 링크가 표시됩니다. |

### 7. 프로젝트 자동 생성 확인

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | ① 저장 직후 알림의 '프로젝트 보기 →' 링크 ② 계약 상세 상단 **[프로젝트 보기 (P번호)]** ③ **현장 > 프로젝트** 목록 ④ **현장 > 공정 보드** '대기중' 칸 |
| **사용 목적** | 계약 '진행' 전환으로 만들어진 프로젝트가 정상 생성됐는지, 계약과 잘 연결됐는지 확인합니다. |
| **등록 순서(확인 순서)** | ① 프로젝트 상세 진입 ② 상단 뱃지 확인 — 프로젝트 상태 '진행 중' + 현재 공정 '대기중' ③ '개요' 탭의 계약 정보에서 **[계약 보기 (C번호)]** 링크로 계약과 왕복 이동 확인 ④ 공사명·현장 주소·계약 총액(VAT 포함)·공급가액이 계약에서 복사됐는지 확인 |
| **필수 입력값** | 없음(자동 생성). |
| **저장 후 확인 위치** | 프로젝트 요약 카드(프로젝트명·고객·현장 주소·상태·현재 공정·계약 총액·확정 매출(공급가액)·지출 총액·실제 순이익·착공일·준공 예정일). 착공일은 아직 비어 있는 것이 정상입니다(실제 착공 시 기록). |
| **수정 방법** | 프로젝트 상세 → **[수정]**. 계약 연결은 바꿀 수 없습니다. |
| **취소·파기 방법** | [20번](#20-프로젝트-취소파기중단) 참고. |
| **주의사항** | **계약 1건당 프로젝트 1건**을 시스템이 강제합니다(중복 생성 원천 차단). 프로젝트 목록에 '새 프로젝트' 버튼이 없는 것은 정상 — 계약 없는 **예외 프로젝트 생성**(하자보수·내부 작업용)은 사장(슈퍼관리자)만 가능하며 생성 사유가 필수 입력·감사 기록됩니다. 예외 프로젝트의 개요 탭에는 "계약 없음(예외 생성)"이 표기됩니다. |

### 8. 공정 보드 대기중 등록 확인

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | **현장 > 공정 보드** (화면 주소 `r=process.board`) |
| **사용 목적** | 진행 중인 모든 공사가 지금 어느 공정 단계에 있는지 한 화면에서 봅니다. 새로 계약된 공사는 첫 칸 **'대기중'** 에 올라옵니다. |
| **등록 순서(확인 순서)** | ① 공정 보드 진입 ② 첫 그룹 **대기중(착공 전 대기)** 칸에서 새 프로젝트 카드 확인 — 최근 진입한 카드가 **맨 위**에 옵니다 ③ 카드 내용 확인: 프로젝트명·상태 뱃지·고객·현장주소·담당 영업·배정 직원·착공(예정)일·다음 일정·등록일·진입일·진행률 ④ 카드를 클릭하면 프로젝트 상세로 이동 |
| **필수 입력값** | 없음(자동 배치). |
| **저장 후 확인 위치** | 보드 상단 요약 5종 — **전체 진행 프로젝트 / 대기중 / 진행 공정 수 / 검수 대기 / 지연 프로젝트**. 이 수치는 대시보드의 같은 이름 수치와 항상 일치합니다. |
| **수정 방법** | 카드 위치(공정)는 드래그 또는 프로젝트 상세 '공정' 탭에서 이동([9번](#9-대기중다음-공정-이동)). |
| **취소·파기 방법** | 해당 없음 — 취소·파기·완료·정산된 프로젝트는 보드에서 자동으로 사라집니다(데이터는 보존). |
| **주의사항** | 보드에는 **진행 예정·진행 중·일시 중단·하자보수** 상태만 표시됩니다. 카드에 정보가 없으면 "직원 미배정" / "일정 미등록" / "착공일 미정"으로 표기되니 다음 단계(배정·일정 등록)를 진행하세요. |

### 9. 대기중→다음 공정 이동

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | 방법 A: **현장 > 공정 보드**에서 카드를 끌어서(드래그) 다음 공정 칸에 놓기. 방법 B: 프로젝트 상세 → **'공정' 탭** → '공정 변경' 폼. |
| **사용 목적** | 공사 진행에 맞춰 카드를 다음 단계로 옮기면 진행률이 자동 계산되고 공정 이력이 남습니다. |
| **등록 순서** | (방법 B 기준) ① 프로젝트 상세 → 공정 탭 ② '이동할 공정' 선택 — 그룹별로 정리됨: **대기중** → **착공준비**(현장실측·도면작성·자재발주·착공준비) → **시공**(양생/보양·고압세척·바탕처리(면처리)·크랙보수·퍼티/퍼팅·방수처리·프라이머·1차도장·2차도장·3차도장(마감)·건조양생) → **마무리**(현장정리·준공검사) → **하자보수** ③ 사유 입력(예: "크랙보수 완료로 다음 공정 진행") ④ **[공정 이동]** |
| **필수 입력값** | 이동할 공정 |
| **저장 후 확인 위치** | 공정 탭의 '공정 진행 현황'(현재 공정 뱃지·진입일·진행률), '공정 이력'(최근 5건, 전체는 '이력' 탭), 공정 보드의 새 칸. |
| **수정 방법** | 잘못 옮겼으면 같은 방법으로 원래 공정으로 다시 이동하면 됩니다(이력이 남아 추적 가능). |
| **취소·파기 방법** | 해당 없음 — 이동 자체를 삭제할 수 없고, 되돌리는 이동을 기록합니다. |
| **주의사항** | 🔒 표시가 있는 공정(크랙보수·방수처리·3차도장(마감)·준공검사·하자보수)은 **확인 필요 공정**으로, 여기에 있는 진행 중 공사는 '검수 대기'로 집계됩니다. 2단계 이상 건너뛰면 "중간 공정을 건너뛰고 이동합니다. 계속하시겠습니까?" 확인 창이 뜹니다. 완료·정산·취소·파기된 프로젝트는 공정 이동이 불가합니다. 이동 권한은 현장관리자·사장에게 있습니다. |

### 10. 직원 배정

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | 프로젝트 상세 → **'직원·일정' 탭** → '배정 추가' 폼 |
| **사용 목적** | 이 공사에 투입되는 직원과 역할·기여도를 기록합니다. 기여도는 직원 성과(순이익 기여) 계산에 사용됩니다. |
| **등록 순서** | ① 검색 칸에 이름·부서·직책 입력 — 아래 선택 목록이 실시간으로 걸러짐 ② 직원 선택(이미 배정된 직원은 "(배정됨)" 표시와 함께 선택 불가) ③ 역할 선택(허용된 역할 목록에서만) ④ 기여도(%) 입력 ⑤ 시작일·종료일(선택) ⑥ **[배정 추가]** |
| **필수 입력값** | 직원, 역할 |
| **저장 후 확인 위치** | 같은 탭의 '배정 직원' 표(이름·역할·기여도·기간·상태), 공정 보드 카드의 "배정 ○○○ (n명)", 대시보드 직원 업무 현황. |
| **수정 방법** | 기여도·기간 변경은 기존 배정을 삭제 후 다시 등록하거나, 개요 탭의 기여도 배분 방식을 확인하세요. |
| **취소·파기 방법** | 배정 행 오른쪽 **[삭제]** → 확인. |
| **주의사항** | 같은 직원을 두 번 배정하면 "이미 이 프로젝트에 배정 중(active)인 직원입니다. 기존 배정을 수정하거나 종료 후 다시 등록하세요."로 거부됩니다. 퇴사·휴직 직원은 "비활성(퇴사·휴직) 직원은 새로 배정할 수 없습니다. (기존 배정 이력은 보존됩니다)"로 거부됩니다. 직원 ID 숫자를 직접 입력하는 방식은 없어졌습니다 — 반드시 이름 검색으로 선택하세요. 배정 권한은 현장관리자·사장에게 있습니다. |

| **메뉴 위치** | **현장 > 일정** → 오른쪽 위 **[+ 새 일정]** (화면 주소 `r=schedule.index`). 프로젝트 상세 '직원·일정' 탭의 **[일정 등록]** 버튼으로도 이동 가능. |
| **사용 목적** | 어느 날짜·어느 시간대에 어떤 직원이 어떤 현장에 가는지 잡습니다. 월 캘린더와 직원별 타임라인 두 가지 보기를 제공합니다. |
| **등록 순서** | ① [+ 새 일정] 클릭(팝업) ② 제목 입력 ③ 참여 직원 체크(여러 명 가능) ④ 날짜 선택 ⑤ **시간대 선택 — 오전/오후/야간 버튼을 눌러 켬(복수 선택 가능, 최소 1개)** ⑥ 프로젝트 연결(선택) ⑦ 유형 선택(작업/회의/현장방문/**휴가**/기타) ⑧ 메모 ⑨ **[저장]** |
| **필수 입력값** | 제목, 참여 직원 1명 이상, 날짜, 시간대 1개 이상 |
| **저장 후 확인 위치** | 월 캘린더·직원별 타임라인(직원 개인색 점 표시), 대시보드의 '오늘 일정', 공정 보드 카드의 '다음 일정', 프로젝트 상세 '직원·일정' 탭. |
| **수정 방법** | [13번](#13-일정-수정) 참고. |
| **취소·파기 방법** | 일정 클릭 → 상세 팝업 → **[삭제]** → "이 일정을 삭제하시겠습니까?" 확인. |
| **주의사항** | 같은 직원이 같은 날짜·시간대에 이미 일정이 있으면 "같은 날짜·시간대에 이미 잡힌 일정이 있습니다." 경고가 뜨고, **[승인하고 저장]** 을 눌러야만 겹쳐서 저장됩니다. 일정 등록·이동 권한은 현장관리자·사장에게 있고, 직원은 본인 일정을 열람합니다. |

> **휴가 등록 (R5 신설)** — 유형을 **'휴가'** 로 선택하면 그 일정이 참여 직원의 휴가로 집계됩니다.
> ① 참여 직원 = 휴가 가는 직원 ② 프로젝트 연결은 비워도 됩니다 ③ **전일 휴가**는 시간대 3개(오전·오후·야간)를 모두 켜거나 종일로 = **1.0일**,
> **반차**는 시간대를 1~2개만 켜면 = **0.5일** ④ [저장].
> 캘린더·타임라인에서 휴가는 직원 개인색 대신 **주황(앰버)색 빗금 + '휴가' 태그**로 구분 표시됩니다.
> 1.0일 휴가는 출근 분석의 '근무 예정 일수'에서 자동 제외되고(반차는 유지), 분석 그리드에 **V**(전일)·**반**(반차)으로 표시됩니다 —
> 집계 기준은 [PRODUCT_MANUAL 15번](PRODUCT_MANUAL.md#15-직원-출근-분석) 참조.
> 휴가가 그 직원의 다른 일정과 겹치면 같은 충돌 경고가 뜹니다(의도한 것이면 [승인하고 저장]).

### 12. 오전·오후·야간 복수 선택

| 항목 | 내용 |

| **사용 목적** | 하루 종일 걸리는 작업(오전+오후), 야간 연장(오후+야간) 등 실제 작업 시간대를 정확히 기록합니다. |
| **등록 순서** | ① 해당하는 시간대 버튼을 눌러 켭니다(다시 누르면 꺼짐) ② 여러 개를 동시에 켤 수 있음 ③ [저장] |
| **필수 입력값** | 최소 1개 시간대 |
| **저장 후 확인 위치** | 캘린더·카드·일정 상세에 선택한 시간대 전체가 "오전 · 야간"처럼 표시됩니다. |

| **취소·파기 방법** | 해당 없음(시간대만 바꾸면 됨). |
| **주의사항** | 하나도 선택하지 않고 저장하면 "시간대(오전/오후/야간)를 1개 이상 선택하세요." 오류가 납니다. 상단 시간대 필터로 조회할 때, 복수 시간대 일정은 **해당하는 모든 시간대 필터에서** 검색됩니다(오전+야간 일정은 '오전' 필터에도 '야간' 필터에도 나옴). 유형이 **'휴가'** 인 일정은 켠 시간대 수로 휴가 일수가 정해집니다 — **1~2개 = 반차 0.5일, 3개 모두 = 1.0일**([11번](#11-일정-등록)의 휴가 등록 참조). |

### 14. 자재비 등록

### 16. 지출 총액 확인

| 항목 | 내용 |
|---|---|
| **메뉴 위치** | ① 프로젝트 상세 상단 '프로젝트 요약'의 **지출 총액** ② '지출' 탭 하단 소계 4종(자재비 소계 / 인건비 소계 / 기타 소계 / 지출 총액) |
| **사용 목적** | 이 공사에 실제로 들어간 돈을 확인하고, 실제 순이익(= 확정 매출(공급가액) − 지출 총액)이 흑자인지 봅니다. |
| **등록 순서(확인 순서)** | ① 지출 탭 진입 ② 구분·작업자·발생일 기간으로 필터 ③ 하단 소계와 지출 총액 확인 ④ 요약 카드의 '실제 순이익' 확인(적자면 빨간색) ⑤ 필요 시 **[CSV 출력]** 으로 내려받아 검토(파일명은 `expenses_...`) |
| **필수 입력값** | 없음(조회 화면). |
| **저장 후 확인 위치** | 대시보드 '이번 달 원가 총액'(발생일 기준), 리포트의 확정 순이익(준공월 기준)에도 반영됩니다. |
| **수정 방법** | 개별 비용을 수정하면 지출 총액이 자동 재계산됩니다. |
| **취소·파기 방법** | 해당 없음. |
| **주의사항** | **지출 총액에는 '확정' 상태 비용만 합산**됩니다(임시 저장·확인 대기·취소 제외 — 화면 도움말에도 명시). 비용이 한 건도 없으면 0원이 아니라 **'미입력'** 으로 표기되며, 이때 실제 순이익도 계산하지 않습니다(미입력 상태로 완료 처리하면 순이익이 과장되니 주의). |

> **'원가'→'지출' 표기 변경 안내 (R5)** — 프로젝트 상세 화면 안의 표기만 바뀌었습니다(탭 '원가'→'지출', '원가 총액'→'지출 총액').
> **값·계산식·화면 주소는 그대로**입니다 — 내부 주소(`r=costs.*`)와 탭 주소(`#costs`)는 바뀌지 않아 기존 북마크도 그대로 동작합니다.
> 대시보드·리포트의 회계 지표('이번 달 원가 총액', '원가 총액(확정 공사)' 등)는 '원가 총액' 표기를 유지하며,
> 프로젝트 상세의 '지출 총액'과 **동일한 값**입니다(화면 도움말에도 "회계 지표의 '원가 총액'과 동일 값"으로 병기).

### 23. 매출·원가·순이익 확인

| 항목 | 내용 |

| **등록 순서(확인 순서)** | ① 리포트에서 기간 선택 ② KPI 확인 — 신규 고객 / 견적→계약 전환율 / 미수금 / 확정 매출(공급가액) 목표달성률 / 확정 순이익 목표달성률 ③ '월별 확정 매출(공급가액)·확정 순이익 추이'(준공월 기준) 차트 확인 ④ 필요 시 CSV 다운로드 |

| **저장 후 확인 위치** | 대시보드 핵심 현황·재무 현황과 동일한 계산식을 사용하므로 수치가 항상 일치합니다. |

### 24. 자주 발생하는 오류와 해결

실제 화면에 뜨는 메시지 그대로 정리했습니다.

| 화면 메시지(실제 문구) | 언제 나오나 | 해결 방법 |
|---|---|---|
| "분할 비율 합계가 100%가 되어야 합니다. (현재 110%)" | 계약 저장 시 계약금+중도금+잔금 비율 합이 100이 아닐 때 | 세 비율을 다시 조정해 합계를 정확히 100으로. 잔금 칸은 자동 계산이니 계약금·중도금만 맞추면 됩니다. |
| "분할 금액이 비율 계산 결과와 일치하지 않습니다. 비율 또는 금액을 다시 확인하세요. (분할 지급 계산 기준: 계약 총액(VAT 포함))" | 비율과 금액이 어긋난 채 저장을 시도할 때 | 비율을 다시 입력하면 금액이 자동 재계산됩니다. 금액을 고쳤다면 비율 칸이 자동으로 따라왔는지 확인 후 저장. |
