# EDEN CRM 회계 기준 (단일 문서)

EDEN CRM 화면의 모든 돈 수치가 따르는 계산 기준을 한 곳에 모은 문서입니다.
계산은 전부 단일 출처 `app/core/AccountingService.php`(원가는 `CostService`)에서 수행되어
대시보드·계약·프로젝트·성과·리포트 화면 간 수치가 항상 일치합니다(자동 대사 테스트로 고정 — 하단 '검증 방법' 참조).

독자: 관리자(사장)·회계 담당. 화면 사용법은 [PRODUCT_MANUAL.md](PRODUCT_MANUAL.md), 절차는 [USER_MANUAL.md](USER_MANUAL.md).
직원별 기여 매출·기여 원가·기여율·목표 달성률의 상세 산식은 [EMPLOYEE_CONTRIBUTION_RULES.md](EMPLOYEE_CONTRIBUTION_RULES.md) 참조.

## 1. 두 축의 분리 — 손익 축과 현금 축

모든 금액은 아래 두 축 중 하나에 속하며, 화면의 모든 카드·컬럼에 어느 축인지 표기되어 있습니다.

| | **손익 축** | **현금 축** |
|---|---|---|
| 단위 | **공급가액 (VAT 제외)** | **계약 총액 (VAT 포함)** |
| 대표 수치 | 확정 매출, 확정/실제 순이익, 직원 성과 기여, 목표 달성률 | 입금 총액, 미수금, 입금률, 분할 지급(계약금/중도금/잔금) |
| 인식 시점 | 확정 매출: **완납일(마지막 정상 입금일)이 속한 달** · 확정 순이익·직원 기여: 준공월 | **입금일(paid_date)** |
| 모집단 | 확정 매출: **완납(순입금 ≥ 계약 총액) 유효 계약** · 확정 순이익: 완료·정산 프로젝트 | 입금완료(paid) 입금 − 환불 |

- `공급가액 + 부가세 = 계약 총액` 이 항상 성립합니다(계약·프로젝트 저장 시 자동 분리 — 견적 연결 시 견적 부가세 비례, 미연결 시 ÷(1+세율)).
- **부가세는 예수금**(나라에 낼 돈)이므로 매출·순이익·성과 어디에도 포함하지 않습니다.
- 완납 전에 받은 계약금·중도금은 손익에 잡히지 않고 현금 축(입금 총액)에만 나타납니다 — 회계상 선수금 성격.

### 매출 인식 = 입금 완료(완납) 기준 (R7 변경)

- **확정 매출(공급가액)** = 유효 계약(삭제·취소·파기 제외) 중 **완납(환불 차감 순입금 ≥ 계약 총액 > 0)** 인 계약의 공급가액.
  귀속 시점은 **완납일(마지막 정상 입금일)**. **프로젝트 완료 여부와 무관**(R7 사장 지시 — 완납 즉시 확정매출 인식).
  draft(작성중) 계약도 완납이면 포함(지시 기준 "파기 아님"). 완납 후 환불로 순입금이 계약 총액 아래로 내려가면 소급 제외.
- **확정 순이익·원가 총액(확정 공사)·직원 확정 기여**는 종전대로 **준공(완료·정산) 기준**을 유지합니다 — 원가는 공사 완료 시점에 확정되기 때문. 따라서 완납했지만 미준공인 달에는 확정 매출과 확정 순이익의 귀속월이 어긋날 수 있습니다.
- 미착공·진행 중 공사는 **예상 매출**로 분리 표기(확정에 섞지 않음).
- **수주액**은 별도 지표 — 계약일 기준, 취소·파기 제외. "이번 달 수주액"과 "이번 달 확정 매출"은 서로 다른 것이 정상입니다.

## 2. 현금 축 산식 — 순입금·미수금·입금률

| 수치 | 산식 | 비고 |
|---|---|---|
| **순입금** | Σ 입금완료(paid) 입금(kind=payment) − Σ 환불(kind=refund) | 대기(pending)·취소(cancelled) 입금 제외 |
| **마지막 입금일** | 정상 입금(paid)의 입금일(paid_date) 최댓값 | 등록·수정일 미사용, 환불 제외, 없으면 "입금 없음" |
| **미수금** | Σ 계약별 max(0, 계약 총액 − 순입금) | 계약별로 0 미만 절사 후 합산 |
| **입금률** | 순입금 ÷ 계약 총액 × 100 | 총액 0원이면 '-' 표기(0% 아님) |

### 미수금 모집단 — 작성중(draft) 제외

미수금 집계 대상 계약은 **계약 진행(active) · 계약 보류(on_hold) · 계약 완료(completed)** 뿐입니다
(코드 상수 `AccountingService::RECEIVABLE_STATUSES`).

- **작성중(draft) 제외** — 아직 도장 찍지 않은 계약은 채권이 아님. 계약 상세에는 「제외(작성중)」로 표기.
- **파기(terminated)·취소(cancelled)·삭제 계약 제외** — 계약 상세·목록에 「제외(파기/취소)」 표기.
- 참고: 이 미수금은 관리회계용입니다. 청구 기준 매출채권과 미청구 계약잔액이 합산된 값이라 **재무제표상 매출채권과 다릅니다**.

## 3. 분할 지급(계약금·중도금·잔금) 규칙

- 세 비율의 합은 **정확히 100%** 여야 하며, 아니면 저장이 차단됩니다("분할 비율 합계가 100%가 되어야 합니다. (현재 …%)").
- 금액 = **계약 총액(VAT 포함)** × 비율(반올림). **반올림 끝자리 차이는 잔금이 흡수**합니다 —
  그래서 잔금 금액 칸은 자동 계산·수정 불가입니다(계약 상세 도움말: "분할 지급 계산 기준: 계약 총액(VAT 포함) · 반올림 보정은 잔금 귀속").
- 저장 시 입금 예정 내역(payments의 대기 행)이 자동 생성·동기화됩니다. **동기화는 대기(pending) 행만** — 이미
  입금완료(paid)된 회차와 환불 행은 절대 변경되지 않고, 이미 받은 금액 합이 새 계획 금액을 초과하면 저장이 차단됩니다.

## 4. 파기·환불 처리

계약 파기 시 아무 데이터도 삭제되지 않습니다(상태 전환 + 기록).

- **환불** = 입금 내역에 `환불(kind=refund)` 행으로 기록 → 순입금에서 차감(현금 축 반영). 환불 한도는 순입금까지.
- **위약금·정산 금액** = 별도 축 기록 전용 — 매출·순이익에 포함하지 않음.
- 파기 시 남은 **대기(pending) 예정 행은 정리**되어 미수금 알림이 더 이상 발사되지 않습니다. 계약 컬럼에 남은 분할 구성(예: 잔금 770만)은
  이력 보존 목적이며, 목록·상세에서 「잔여 회차 청구 중단」으로 안내되고 입금률은 '-' 처리됩니다.
- 파기·취소 계약은 미수금·계약 완료 수 집계에서 제외됩니다.
- **입금 물리 삭제 금지** — 입금 내역은 삭제 대신 취소(cancelled) 전환(R3 도입)이며, 취소 입금은 모든 집계에서 제외되고 감사 로그에 남습니다.

## 5. 견적 금액 산식 (R5 확정)

견적서 항목의 금액과 합계는 아래 산식으로 계산됩니다. 화면(견적 등록/수정 폼)의 자동 계산은 표시용이며,
**저장 시 서버가 항상 같은 산식으로 재계산**합니다(서버가 최종 권위 — 화면 값을 그대로 믿지 않음).

- **항목 금액 = 기본금액 + 재료비 + 인건비 + 장비비 + 외주비 + 기타비용**
  - 기본금액 = 면적(㎡)을 입력했으면 **면적 × 수량 × 단가**(단가 = 원/㎡), 면적 미입력이면 **수량 × 단가**.
- **공급가액(VAT 제외) = 항목 금액의 합** · **부가세 = 할인 전 공급가액 × 세율** · **총액(VAT 포함) = 공급가액 + 부가세 − 할인** — 파생 규칙은 기존 그대로.
- R5 이전에는 비용 5종(재료비·인건비·장비비·외주비·기타비용)이 항목 금액에 **합산되지 않는 결함**이 있었습니다(단가만 반영) —
  R5 에서 수정되었고, 견적 상세·인쇄·계약 전환 화면은 모두 같은 저장값을 쓰므로 전 경로가 일치합니다.

### 기존 견적 Q2026-0001 미보정 보류 — R6 에서 자연 해소

- R5 견적 산식 수정 전 저장값이 새 산식과 다른 유일한 견적이 **Q2026-0001(v1)** 이었고, 계약 C2026-0001 연결(계약 스냅샷 대사 보호)로 자동 보정에서 제외해 **정책 확인 대기(hold)** 상태였습니다.
- **R6 시드 리셋(T2)에서 개발 더미 견적이 전부 제거**되면서 이 견적도 소멸했고, 신규 견적은 전부 새 산식 저장 경로만 타므로 **보류가 자연 종결**되었습니다(근거: `.superpowers/sdd/r6-seed-report.md` §4).
- 운영 DB 에 산식 개정 전 저장된 견적이 유입될 경우에만 다시 검토가 필요하며, 그때는 점검 도구 `scripts/quote_amount_dryrun.php`(기본 **보고만**, `--fix` 도 **계약 미연결 견적만** 보정)로 후보를 확인합니다.

## 6. 원가 — 확정만 합산, 두 가지 귀속 축

- **원가 총액 = '확정(confirmed)' 상태의 실적(actual) 비용만 합산.** 임시 저장·확인 대기·취소 비용은 불포함(화면 도움말에도 명시).
- **표기 매핑(R5)** — 프로젝트 상세 화면에서는 이 값을 **'지출 총액'** 으로 표기합니다(탭 이름도 '원가'→'지출').
  **'지출 총액'(프로젝트 화면 표기) = '원가 총액'(회계 지표)** — 같은 값·같은 산식이며 이름만 다릅니다(화면 도움말에
  "회계 지표의 '원가 총액'과 동일 값" 병기). 대시보드·리포트의 회계 지표('이번 달 원가 총액'·'원가 총액(확정 공사)' 등)는
  '원가 총액' 표기를 유지하고, 내부 데이터·화면 주소(`r=costs.*`)도 변경 없습니다.
- 비용이 한 건도 없으면 0원이 아니라 **'미입력'** 으로 표기하고 실제 순이익도 계산하지 않습니다(순이익 과장 방지).
- 비용 취소는 삭제가 아니라 상태 전환(기록 보존)이며 원가 총액이 즉시 재계산됩니다.
- **원가의 두 귀속 축(둘 다 정상 — 기준이 다름)**:

| 수치 | 귀속 기준 | 쓰임 |
|---|---|---|
| 대시보드 **"이번 달 원가 총액"** | **지출 발생일(spent_date)** | 이번 달 돈이 얼마나 나갔나(현금 관점) |
| **"원가 총액(확정 공사)"** · 확정 순이익의 원가 | **준공월 귀속**(완료 공사의 원가) | 그 공사로 실제 얼마 남았나(손익 관점) |

- 대시보드 **"최근 출금(원가 지출)"** 리스트 = 확정 원가의 지출일 순. 파기 **환불은 원가가 아니므로 이 리스트에 나오지 않으며**,
  '최근 입금' 리스트의 「환불 −금액」 배지로 표시됩니다(환불의 '출금' 포함 여부는 **정책 미확정** — 아래 §8).

## 7. 직원 성과 귀속

- **확정 기여 = 완료(정산 포함) 프로젝트만** × 배정 기여도(%). 진행 중 공사는 확정 기여에 넣지 않음(과대 계상 방지).
- 담당(영업)과 참여(배정 기여도)를 구분해 한 프로젝트의 매출·순이익을 여러 직원에게 중복 합산하지 않습니다.
- 평균 순이익률은 가중 평균(귀속 순이익 ÷ 귀속 매출). 분모 0·목표 미설정·데이터 부족은 0이 아니라 '-'·"목표 미설정"·"산출 불가"로 구분 표기.
- **한 프로젝트에 배정된 전 직원의 기여 순이익 합 = 그 프로젝트의 확정 순이익**(항등). 회사 전체로도 **Σ 직원 확정 기여 = 회사 확정 순이익**이 항상 성립합니다(R6 회계 검수에서 1원 대사 확인). 기여 매출·기여 원가·기여율(배분방식 main/ratio/role)·목표 달성률의 산식은 **[직원 기여 규칙 — EMPLOYEE_CONTRIBUTION_RULES.md](EMPLOYEE_CONTRIBUTION_RULES.md)** 를 보세요.

## 8. 알려진 트레이드오프 (시스템이 의도적으로 감수한 것)

전문가 점검(R3·R4 planner)과 R5 라운드에서 확인된, **오류가 아니라 설계상 감수한 한계**입니다. 운영 시 아래를 전제로 수치를 읽으세요.

| # | 항목 | 내용 |
|---|---|---|
| 1 | **위약금·정산금 수익 미인식** | 재무회계상 위약금은 잡이익 인식 대상이나, CRM 은 별도 축 기록만 하고 매출에 넣지 않음(보수적 선택). 실제 수취 여부 추적 기능도 없음 — 수취 확인은 입금 내역·통장 대사로 |
| 2 | **세금계산서(세무) 축 부재** | 회차별 세금계산서 발행일·발행 여부를 관리하지 않음 — 부가세 신고 대사는 시스템 밖(홈택스). 향후 보완 후보 |
| 3 | **완성(준공월) 기준의 쏠림** | 해를 넘기는 장기 공사는 매출이 준공월에 몰림(진행기준 아님). 도장공사 대부분이 단기라 감수 |
| 4 | **'실제 순이익' = 공헌이익** | 프로젝트 직접원가만 차감 — 본사 공통비(사무실·보험·간접 인건비 등) 미반영. "회사 순이익"으로 읽지 말 것 |
| 5 | **완료→재개 시 확정 매출 소급 변동** | 완료를 재개하면 준공일이 해제되어 지난달 확정 매출이 줄 수 있음(사유 필수·이력 기록으로 추적). 월 마감 기능은 아직 없음 |
