### 정책/후속 검토 (코드 수정 대상 아님 — 이관)

- **계정 열거 메시지**(보안): 비활성 계정 안내·계정별 잠금 메시지가 아이디 존재를 노출. 내부 4인 CRM UX 트레이드오프라 직접 변경 보류 — **정책/후속 검토**(IP 스로틀 구조 필요).
- **`session_write_close` 조기해제**(성능): 읽기전용 JSON 폴링의 세션 잠금 조기 해제. 전 라우트 세션쓰기(인증·유휴·CSRF) 선행 재구조화 필요 — **정책/후속 검토**.
- **대시보드 당월 집계 메모이제이션**(성능): boss 대시보드에서 당월 지표 ~10회 독립 재계산(데이터 무관 상수). memoization 은 POST 스테일 위험 — **정책/후속 검토**.
- **.htaccess 운영 실효**: 로컬 `php -S` 는 .htaccess 미해석이라 정적 검토만 수행 — 운영 Apache 실측은 T12 배포 단계 인계(내부 경로 403·업로드 PHP 실행 차단).

## 참고 — 결함이 아닌 것 (설계된 동작)

1. **파기 계약 수정 차단이 오류 화면이 아니라 안내 이동**으로 처리됨("파기된 계약은 수정할 수 없습니다") — R3 설계 그대로, 상태 보호 정상.
2. **공정 보드에 완료 프로젝트가 안 보임** — 보드는 진행 예정·진행 중·일시 중단·하자보수 상태만 표시(R3 설계). 전체완료 확인은 프로젝트 상세에서.
3. **진행률 분모가 19단계로 전환** — 옛 시드 값과 1회성 차이가 있을 수 있으나 공정 이동 시 자동 수렴.

## 재검 방법 (수치가 의심될 때)

1. 자동 검증 3종 실행 — 전부 통과가 정상:
   ```bash
   bash scripts/run_acct_tests.sh     # 회계 산식·대사 (R4 기준 46 PASS)
   php  scripts/reconcile_qa.php      # 화면 = DB 대사 (30/30)
   bash scripts/qa_smoke.sh           # 권한·기능 스모크 (33/33)
   ```
2. 화면 스팟 대사 — 사장 대시보드 핵심 현황 4카드 값을 클릭해 근거 화면(계약 목록·리포트)과 비교. 카드와 근거 화면은 같은 계산식을 쓰므로 항상 일치해야 합니다.
3. 기간 필터 경계 확인 — 견적·계약·파이프라인에서 같은 프리셋(예: 이번 달)을 눌러 날짜 입력 칸에 표시되는 경계가 세 화면 동일한지 확인.
4. 불일치 발견 시 — 감사 로그로 최근 변경을 확인하고, 원문 QA 보고서의 해당 섹션 실측 절차를 재현합니다.

*판정 기준·시드 값 등 세부 수치는 원문 `.superpowers/sdd/r4-qa-report.md` 를 보세요. 회계 수치의 정의는 [ACCOUNTING_RULES.md](ACCOUNTING_RULES.md) 참조.*
