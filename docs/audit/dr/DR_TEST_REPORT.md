### 🔴 치명 결함 1 — 보유 DB 백업 14개 전부 무보정 복구 불가

```
ERROR 3105 (HY000) at line 1224:
The value specified for generated column 'active_pair'
in table 'edencrm_project_assignments' is not allowed.
```

- **원인**: `deploy/db_dump.php` 가 `SELECT *` 결과를 컬럼 목록 없이 `INSERT INTO t VALUES (...)` 로 기록.
  `edencrm_project_assignments.active_pair` 는 `GENERATED ALWAYS AS (...) VIRTUAL` 컬럼인데
  그 값까지 INSERT 값 목록에 포함된다. 생성 컬럼에는 값을 넣을 수 없다(MySQL 3105 / MariaDB 1906).
- **실측 영향**: 덤프가 `DROP TABLE IF EXISTS` 46개로 시작하므로 **46개를 전부 지운 뒤
  23/46 지점에서 중단** → 23개 테이블 미복원. 여기에 `users`(7행), `projects`(11행),
  `settings`(15행), `role_permissions`(77행)이 포함 → **계정 0건 = 로그인 불가**한 반쯤 빈 DB.
- **범위**: `database/backups/` 의 DB 백업 **14개 전량**. 무보정 복구 가능 = **0개**.
- **판정 구분**: 복구 절차 문제가 아니라 **백업본 자체 결함**.
- **조치**: `db_dump.php` 수정(§5) + 기존 백업용 복구변환 도구(`repair_dump.php`) 작성.

### 🔴 치명 결함 2 — 백업이 단일 장애점 (미해결)

- git 원격 저장소 **0개**, `database/backups/` 는 `.gitignore` 로 git 제외, 오프사이트 사본 0, Time Machine 미설정.

### 실제 장애 시 복구 가능 여부 — 조건부

**가능한 것**: 백업 파일이 손에 있고 복구 대상 서버가 준비돼 있다면,

**막힐 수 있는 것 — 세 가지**:
1. **백업 사본이 맥북 1대뿐**. 그 디스크가 죽으면 복구할 백업 자체가 없다. (치명 결함 2)

3. **최대 4일치 데이터가 애초에 백업되지 않았을 수 있다** (RPO 무제한).

즉 **"복구 기술은 검증됐으나, 복구 체계는 아직 미완성"** 이다.

| 4 | 백업에서 `config.local.php` 제외 또는 아카이브 암호화 | 백업 유출 = 운영 DB 자격증명 유출 (mode 644 평문) |
| 5 | `rollback.sql` 을 46테이블로 갱신 | 현재 39/46, 7개 누락 |
| 6 | `deploy.sh` 에 `--delete` 검토 | 운영 잔존 파일 4개 (노출은 차단됨) |
| 7 | 배포 **직후** 백업 추가 | 현재 배포 직전만 → 최신 배포분에 대응하는 백업이 항상 없음 |

### 이번 테스트로 수정 완료된 항목

`deploy/db_dump.php` 3건 + 1건:
1. 생성 컬럼 제외 + 명시적 컬럼 목록 INSERT (치명 결함 1 근본 수정)
2. `SET NAMES utf8mb4` 선언 추가 (한글 파손 방지)
3. `START TRANSACTION WITH CONSISTENT SNAPSHOT` (비원자적 덤프 해소)
4. `date_default_timezone_set('Asia/Seoul')` (파일명 타임존 통일)
5. `SHOW TABLES` → `information_schema` BASE TABLE 한정 (뷰 혼입 시 덤프 파손 예방)

수정 후 **신규 백업을 실제로 생성해 무변환 import 성공(rc=0)** 및 운영 대조 불일치 0건 실증.
